Rustling Spots 1.21.1

Custom Spot Definitions

Cette page explique le nouveau systeme de Rustling Spots base sur les datapacks. Le but est simple : permettre aux joueurs, serveurs et modpacks de creer leurs propres rustling spots via quelques fichiers JSON, sans textures custom, sans modeles, sans API addon et sans systeme de scripts.

Ce que vous personnalisez Les biomes, les blocs, la priorite, le poids, la famille Pokemon, la famille de loot et les particules.
Ce qui reste partage Le rendu, l'animation, le timing, le comportement et la famille visuelle choisie via visual_family.
Datapack d'exemple inclus Le pack custom_swamp_spot_pack montre deja un cas complet et fonctionnel.

Etat du Datapack Exemple

Oui, le datapack exemple est pret et complet pour les tests, la comprehension du systeme et comme base a dupliquer pour vos propres packs.

Le pack inclut deja un custom spot complet, une famille Pokemon custom, une famille de loot custom, un nom lisible pour le chat et un fichier README d'installation. 
example_datapacks/custom_swamp_spot_pack/
|- pack.mcmeta
|- README.txt
`- data/
   `- rustlingspots/
      `- rustling_spots/
         |- spot_definitions/
         |  `- swamp.json

Une fois copie dans world/datapacks/, il suffit de lancer /reload puis de tester avec /rustlingspots spawn rustlingspots:swamp_custom.

Vue d'Ensemble

Un custom rustling spot n'est pas un nouveau type visuel complet. C'est une definition de spawn qui reutilise le comportement standard de Rustling Spots.

  • Le rendu utilise la famille definie par visual_family, ou le fallback historique grass.
  • L'animation reste la meme.
  • Le timing reste le meme.
  • La logique de spawn s'integre directement au systeme normal du mod.
  • La selection se fait avec priorite puis poids.
  • Le spot peut etre invoque avec une commande.
  • Le tout est rechargeable avec /reload et /rustlingspots reload.

Structure du Datapack

Le systeme repose sur trois groupes de fichiers. Chaque groupe a un dossier bien precis dans le datapack.

Type Emplacement Role
Spot definitions data/<namespace>/rustling_spots/spot_definitions/*.json Definit les spots eux-memes.
Pokemon families data/<namespace>/rustling_spots/pokemon_families/*.json Definit les pools Pokemon reutilisables.
Loot families data/<namespace>/rustling_spots/loot_families/*.json Definit les pools de loot reutilisables.

Namespace

Le namespace est la premiere partie de l'identifiant, avant les deux-points. Par exemple, dans rustlingspots:swamp_custom, le namespace est rustlingspots et le nom est swamp_custom.

Vous pouvez utiliser votre propre namespace comme mymodpack ou myaddon, mais l'exemple fourni utilise directement rustlingspots pour rester plus parlant.

Fichier du Spot

Chaque custom spot est defini dans un fichier JSON situe dans spot_definitions.

Exemple Complet

{
  "format_version": 1,
  "id": "rustlingspots:swamp_custom",
  "display_name": "Swamp Spot",
  "priority": 10,
  "weight": 5,
  "visual_family": "leaves",
  "dimensions": [
    "minecraft:overworld"
  ],
  "biomes": [
    "minecraft:swamp",
    "minecraft:mangrove_swamp",
    "#minecraft:is_forest"
  ],
  "blocks": [
    "minecraft:mud",
    "minecraft:grass_block",
    "#minecraft:dirt"
  ],
  "pokemon_family": "rustlingspots:swamp",
  "loot_family": "rustlingspots:swamp",
  "particles": [
    {
      "type": "rustlingspots:grass_burst",
      "weight": 7
    },
    {
      "type": "minecraft:happy_villager",
      "weight": 3
    }
  ]
}

Champs Disponibles

Champ Obligatoire Description
format_version Oui Version du format. Actuellement : 1.
id Oui Identifiant complet du spot, comme rustlingspots:swamp_custom.
display_name Non Nom lisible affiche dans le chat et les messages. Si absent, l'id brut est utilise.
priority Oui Priorite du spot quand plusieurs definitions correspondent au meme emplacement.
weight Oui Poids utilise apres le filtrage par priorite.
dimensions Non Liste des dimensions autorisees. Si absent, le spot est limite a l'Overworld.
biomes Oui Liste de biomes ou tags de biome autorises.
blocks Oui Liste de blocs ou tags de blocs autorises sous le spot.
pokemon_family Oui Famille Pokemon utilisee par le spot. Peut etre built-in ou definie dans le datapack.
loot_family Oui Famille de loot utilisee par le spot. Peut etre built-in ou definie dans le datapack.
particles Oui Liste de particules ponderees. Seuls type et weight sont supportes.

Biomes et Blocs

Les listes biomes et blocks supportent deux formes :

  • un identifiant direct, comme minecraft:swamp ou minecraft:mud
  • un tag, comme #minecraft:is_forest ou #minecraft:dirt

Particules

Le systeme de particules reste volontairement minimaliste. Chaque entree contient uniquement un type et un poids. 

"particles": [
  { "type": "rustlingspots:grass_burst", "weight": 7 },
  { "type": "minecraft:happy_villager", "weight": 3 }
]
  • Pas de vitesse.
  • Pas d'offset.
  • Pas de controle avance.
  • Les particules invalides retombent sur les particules de fallback de la famille visuelle.
Un custom spot ne cree pas un nouveau systeme de rendu complet. Utilisez visual_family et les particules pour adapter son identite visuelle.

Fichier Pokemon

Les Pokemon ne se definissent pas directement dans le spot. Le spot pointe vers une famille Pokemon, et cette famille contient les entrees du pool.

Emplacement

data/<namespace>/rustling_spots/pokemon_families/<nom>.json

Exemple

[
  { "species": "wooper", "weight": 10, "min_level": 1, "max_level": 18 },
  { "species": "paldean-wooper", "weight": 10, "min_level": 1, "max_level": 18 },
  { "species": "lotad", "weight": 9, "min_level": 1, "max_level": 20 },
  { "species": "surskit", "weight": 9, "min_level": 1, "max_level": 20 },
  { "species": "croagunk", "weight": 8, "min_level": 8, "max_level": 24 },
  { "species": "stunfisk", "weight": 6, "min_level": 12, "max_level": 28 },
  { "species": "marshtomp", "weight": 3, "min_level": 18, "max_level": 36 },
  { "species": "quagsire", "weight": 3, "min_level": 18, "max_level": 36 },
  { "species": "swampert", "weight": 1, "min_level": 36, "max_level": 55 }
]

Champs Utiles

  • species : l'espece Cobblemon.
  • weight : le poids de selection.
  • min_level : niveau minimum possible.
  • max_level : niveau maximum possible.
  • shiny : optionnel, pour forcer une entree shiny.
  • shinyChance : optionnel, pour definir une chance shiny propre a cette entree.

Liaison Avec le Spot

Si le fichier est ici : 

data/rustlingspots/rustling_spots/pokemon_families/swamp.json

alors l'identifiant de famille est : 

"pokemon_family": "rustlingspots:swamp"

Fichier Loot

Le systeme de loot suit exactement la meme logique : le spot ne contient pas les items lui-meme, il reference une famille de loot.

Emplacement

data/<namespace>/rustling_spots/loot_families/<nom>.json

Exemple

[
  { "item": "minecraft:slime_ball", "min": 1, "max": 3, "weight": 5 },
  { "item": "minecraft:vine", "min": 1, "max": 3, "weight": 4 },
  { "item": "minecraft:lily_pad", "min": 1, "max": 2, "weight": 3 },
  { "item": "minecraft:mud", "min": 2, "max": 5, "weight": 4 },
  { "item": "minecraft:mangrove_propagule", "min": 1, "max": 2, "weight": 2 },
  { "item": "cobblemon:pecha_berry", "min": 1, "max": 2, "weight": 3 },
  { "item": "cobblemon:net_ball", "min": 1, "max": 1, "weight": 2 },
  { "item": "cobblemon:great_ball", "min": 1, "max": 1, "weight": 2 }
]

Champs Utiles

  • item : l'identifiant de l'item.
  • min : quantite minimum.
  • max : quantite maximum.
  • weight : poids de selection.

Liaison Avec le Spot

"loot_family": "rustlingspots:swamp"
Si une famille de loot est inconnue, le jeu ne crash pas. Le spot retombe sur le global loot a la place.

Regles de Fonctionnement

Selection de Spawn

  1. Le systeme rassemble toutes les definitions valides pour la position.
  2. Il garde uniquement celles qui ont la plus haute priorite.
  3. Il choisit ensuite la definition finale selon le poids.

Validation et securite

  • Le serveur ne doit jamais crasher a cause d'un mauvais datapack.
  • Un pokemon_family inconnu desactive la definition du spot.
  • Un loot_family inconnu retombe sur le global loot.
  • Des particules invalides retombent sur les particules de fallback de la famille visuelle.
  • Si dimensions est absent, le spot est considere Overworld only.

Ids reserves

Les ids internes du mod ne peuvent pas etre ecrases par datapack. Par exemple, ceci est refuse : 

"id": "rustlingspots:grass"

Les ids internes reserves sont : 

rustlingspots:grass
rustlingspots:sand
rustlingspots:water
rustlingspots:snow
rustlingspots:leaves
rustlingspots:cave
rustlingspots:netherflamme
rustlingspots:soulflame
rustlingspots:flying

Commandes et Reload

  • /rustlingspots spawn rustlingspots:swamp_custom : spawn du spot custom.
  • /rustlingspots spawnshiny rustlingspots:swamp_custom : spawn d'une version shiny.
  • /rustlingspots scan 64 : scan des spots actifs autour du joueur.
  • /reload : recharge les datapacks et les custom spot definitions.
  • /rustlingspots reload : recharge les fichiers Rustling Spots et rafraichit aussi les donnees datapack.
En pratique, si vous modifiez un JSON du datapack pendant les tests, vous pouvez simplement faire /reload puis retester.

Comment Creer Son Propre Spot

1
Dupliquez le dossier custom_swamp_spot_pack pour partir d'une base fonctionnelle.
2
Renommez le spot dans spot_definitions avec un nouvel id et un display_name lisible.
3
Adaptez les listes biomes, blocks, priority, weight et particles.
4
Editez votre famille Pokemon pour choisir les especes, les poids et les niveaux.
5
Editez votre famille de loot pour choisir les items, quantites et poids.
6
Installez le datapack dans world/datapacks/, faites /reload, puis testez avec la commande de spawn.

Exemples de noms propres

  • mymodpack:swamp_custom
  • myaddon:haunted_forest
  • rustlingspots:swamp_custom

A eviter

  • Reprendre un id interne comme rustlingspots:grass
  • Mettre des poids a zero ou negatifs
  • Oublier les champs obligatoires
  • Definir directement Pokemon et loot dans le fichier du spot

Conseils Avant Publication

Avant de partager votre datapack a des joueurs ou de l'integrer a un modpack, il est recommande de verifier les points suivants.

  • La commande de spawn fonctionne avec l'id complet du spot.
  • Le chat affiche bien le display_name et non un id peu lisible.
  • Les recompenses viennent bien de la famille custom attendue.
  • Les Pokemon viennent bien de la famille custom attendue.
  • Le spot apparait naturellement dans les bons biomes et sur les bons blocs.
  • Un /reload reprend correctement les modifications du datapack.
  • Un JSON invalide produit un warning sans faire crasher la partie ou le serveur.

Resume pratique pour les joueurs

Copiez le dossier du datapack dans world/datapacks/, lancez le monde, faites /reload, puis testez avec /rustlingspots spawn rustlingspots:swamp_custom.

Le datapack exemple fourni est deja une bonne base pour creer des variantes de swamp, forest, desert, cave ou tout autre biome personnalise, tout en restant dans un systeme leger, lisible et simple a partager.

En bref : le pack d'exemple est pret, il montre le format complet supporte aujourd'hui, et cette page peut servir de presentation publique ou de documentation pour les joueurs.
